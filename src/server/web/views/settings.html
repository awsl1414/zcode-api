连接

客户端请求没写 model 时用这个模型兜底。

从请求内容推断会话，让同一段对话拿到稳定的会话 id（缓存亲和，也更像官方客户端）。

推断出的会话闲置这么久就算过期，之后的请求按新会话处理。

最多同时记住多少个会话，超出的按最久未用淘汰；是本进程的内存上限。

透传：客户端说了算，代理不改写。覆盖：所有推理模型的请求统一按下面选的档位出线。

覆盖模式生效；透传时仅保存不参与逻辑。关闭 = thinking 禁用（glm-5.3-flash 有效；glm-5.3 上游无法真正禁用，等同最低档）。
