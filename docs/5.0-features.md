# 5.0 支持的功能

本文列出当前代码实际提供的功能。命令、路径、端点与配置键以代码为准；本文不记录方案讨论与实施过程。

## 运行方式

运行时是 Bun 1.4.4，仓库内所有入口都从 `src/index.ts` 启动。

- 不带参数启动：起代理服务并打开网页面板。无 TTY 或容器里用 `-- --no-panel` 或 `-- --cli serve` 关掉面板。
- `--cli` 进入子命令模式：`serve`、`auth`、`claim`、`quota`、`logs`、`routing`、`risk`、`version`。
- `bun run dev` 开发启动；`bun run typecheck` 类型检查；`bun test` 全量测试。
- 编译产物有 `build` 与 `build:linux-x64`、`build:linux-arm64`、`build:darwin-x64`、`build:darwin-arm64` 五个脚本（`build` 产出本机平台的 `zcode-proxy.exe`，发版矩阵另加 `bun-windows-x64`）。它们先跑 `scripts/build-fork-worker.ts` 生成验证码 worker 的 bundle，再 `bun build --compile` 打进单文件二进制。从源码运行不需要这一步。

配置入口是 `config.yaml`（首次启动自动生成），面板设置页写回同一文件。`src/config/template.ts` 与 `config.example.yaml` 是双写契约。`ZCODE_*` 环境变量优先级高于配置文件。版本号两处：`src/version.ts` 的 `VERSION` 与 `package.json` 的 `version`。

## 入站协议

本地客户端可以用三套协议发请求，数据面的 API key 由 `auth.requireKey` 与 `apikeys/` 表门控。

| 端点 | 处理 |
| --- | --- |
| `/v1/chat/completions` | OpenAI Chat 格式，经 `translator/openai-to-anthropic.ts` 翻译后出线，下行反向翻译并转 SSE |
| `/v1/responses` | 先由 `responses-to-chat.ts` 收敛成 Chat 形态，下行经 `chat-to-responses.ts` 还原；有状态存储 `responses/store.ts` 在内存保留 24 小时 |
| `/v1/messages` | Anthropic 格式，只改写 body 后直传（`decompress: false`，压缩字节与 `Content-Encoding` 原样透传） |
| `/v1/models` | 模型清单；能力事实在 `provider/models.ts`，展示清单由 `config.models` 决定 |
| `/async/v1/*` | 闲时通道，默认关闭，走票券队列与 bridge |
| `/mcp` | 官方插件工具聚合为一个端点，工具名形如 `{plugin}__{tool}`，目录 `src/mcp/official-catalogue.json` |
| `/quota` | 实时额度快照 |
| `/health` | 健康检查 |
| `/panel` | 可选网页面板，登录页（`/login`）+ `users.json` 会话门控 |

模型能力（上下文窗口、最大输出 token、推理预算）钉在 `provider/models.ts`，由 `translator/openai-to-anthropic.ts` 消费并钳制。

## 上游仿冒层

两档套餐的上游都是 Anthropic 格式。以下各层在 `proxy/handler.ts` 的 `proxyRequest()` 出线前独立叠加，彼此 fail-open：

| 层 | 位置 | 作用 |
| --- | --- | --- |
| 身份头 | `proxy/identity.ts` + `config.identity` | User-Agent / X-Title / X-ZCode-*；appVersion 在 `src/config/loader.ts` |
| 客户端签名 V4 | `proxy/client-signing.ts` | Ed25519 握手、每请求签名与 PoW，仅 coding-plan 路径；签名模板用真换行连接 |
| 端点改写 | `proxy/endpoint-routing.ts` | 拉 `/api/v1/agent/configs` 的 mapping，把 anthropic 端点改写到 `zcode.z.ai/api/v1/ultra*` |
| 会话亲和 | `proxy/session-context.ts` + `client-session.ts` | 推断稳定的 `x-session-id`，也是 highspeed 的 task_id 来源 |
| 加速卡 | `highspeed/manager.ts` | 后台约 1 秒心跳抽卡，空闲自熄 |
| 验证码 | `src/captcha/` | 仅 start-plan；happy-dom 求解，worker fork 与 CPU governor 按需加载 |
| 传输编码 | `proxy/ordered-transport.ts` | 按 `Accept-Encoding` 偏好排序发送 |

另有 `body-transformer.ts`、`system-prompt.ts`、`trace-headers.ts`、`dump.ts` 分别管 body 改写、系统提示词、追踪头与请求转储。系统提示词运行时真源是 `src/proxy/zcode_system.json`（sidecar）。

## 账号、调度与额度

账号凭据加密存在数据目录，多账号由 `src/accounts/` 下的 broker / scheduler / quota / health / routing 分工处理。

- 账号支持登录导入、启停、并发上限、调度权重、每账号出口代理；控制命令与 `zcode-proxy auth account` 命令族见下表。
- 额度采样有周期采样与启动首轮探测。启动探测覆盖全部账号，包含停用账号：停用只决定参不参与调度，账号页仍要展示额度。采样写入样本与能力对齐，不改健康状态与启停标记。
- 调度与健康层处理租约、并发、粘性、路由级熔断、业务码终态分类与冷却恢复；错误码由产生点落下，日志、统计与控制面三个出口同源。
- 请求记录写 `requests.jsonl`，是日志、用量统计与调试的唯一真源。`getUsageStats` 单遍倒序扫描它，输出总量、时序、七维分组（账号 / 路由 / 模型 / API key / 协议 / 客户端 / 推理强度；面板展示前六维）、按 errorCode 折叠的错误分布、调度事件与缓存命中率。
- 抢限量套餐的 `claim/` 默认开启，按 5 分钟轮询；`previewClaimPlans` 实时拉两面活动清单，只在手动或进屏时触发，不参与轮询。活动排序由 `claim.policy` 决定（默认 `upstream-priority`），没有静态的套餐 ID 优先级列表。
- `async/` 闲时通道默认关闭。所有后台定时器都 `unref()`，不自持进程。

## 控制面与面板

`src/control/control.ts` 是命令表。三个消费者按同一份 `ControlCommand` 发请求：面板走进程内 `POST /api/control`，CLI 转发与 serve 回环监听走 `POST /control`。回环监听恒绑 127.0.0.1，每请求复查 `remoteAddress`。

命令面按域分组：

| 域 | 命令 |
| --- | --- |
| 运行态与日志 | `status`、`shutdown`、`getLogs`、`getRequests`、`getRequestsHistory` |
| 账号 | `listAccounts`、`addAccount`、`removeAccount`、`setAccountEnabled`、`setAccountConcurrency`、`setAccountWeight`、`resetAccountOverrides`、`importAccount`、`exportAccounts` |
| 登录 | `startOAuth`、`deliverOAuthCode` |
| 额度与统计 | `quota`、`getUsageStats`、`getHealthObservation` |
| 路由与风控 | `getRoutingPolicy`、`setRoutingPolicy`、`getRiskReport` |
| API key | `listApiKeys`、`createApiKey`、`setApiKeyEnabled`、`resetApiKeyUsage`、`deleteApiKey` |
| 出口代理 | `listProxies`、`addProxy`、`setProxy`、`removeProxy`、`setAccountProxy` |
| 抢活动 | `getClaimOverview`、`previewClaimPlans`、`listClaimPlanChoices`、`claimNow` |
| 其它 | `checkUpdate`、`detectAppVersion` |

`shutdown` 的退出时序在 `server/control-surface.ts`：先应答，再走与 SIGINT/SIGTERM 同一条路径。没有接 `onShutdown` 的入口回 `shutdown_unavailable`。

网页面板在同一端口提供八个视图：概览、统计、聊天、账号、路由策略、API key、设置、日志。面板骨架由 `src/server/web/page.ts` 的三个数组拼出，顺序即 CSS 层叠、DOM 与依赖语义，`page.test.ts` 逐段核对。

- 概览：风控告警横幅、八张指标卡（前四张来自状态载荷，后四张取自今日用量）、今日 token 时序缩略、并发曲线、账号状态摘要、抢活动汇总行。
- 统计：范围切换、token 时序（按小时 / 按天）、六维分组表、错误分析、调度事件、缓存命中率、365 天活跃热力图。
- 账号：账号表格与筛选、批量操作、套餐详情大窗（含抢活动）、导出导入，出口代理表在页内抽屉里。
- 路由策略：降级顺序、调度策略、队列、粘性、风控与账号矩阵。
- 设置：连接与服务在主区，账户独立一层，功能开关与身份在默认折叠的高级区，版本与退出进程在页脚。改动逐字段保存，端口与绑定地址需要重启才生效。「当前活动」是只读清单，进页时由 `listClaimPlanChoices` 拉一次，页内「刷新活动」按钮再拉。
- 日志：请求事件与系统流两个 tab，筛选、搜索、导出、暂停、清空。
- 聊天：会话、图片附件与流式回复，是面板内的一个视图。
- API key：创建、启停、重置用量、删除。

面板支持中文与英文两套字典、明暗主题、顶栏刷新按钮（按当前视图派发）。所有视图共用一条内容列，可读上限落在卡片、表格、图表与字段格上。

## 可观测面

- 日志页的请求事件读内存最近记录，历史分页读 `requests.jsonl`；系统流走 SSE 增量日志。
- 统计页的六个分组维度全部保留，协议与客户端即使只有一两个值也不删，它们是排查时的分类依据（`byReasoningEffort` 由后端一并算出，面板暂不展示）。
- 错误分析按 errorCode 折叠，一行一个错误身份，用户词与处置建议来自 i18n，不按错误消息前缀猜分类。
- 顶栏刷新按视图分工：概览重拉 `/api/state` 与统计，账号页带 focusedLabel 分级采额度，统计页按当前范围重拉，聊天与系统日志 tab 置灰。

## 构建与发布

CI 是 `bun run typecheck` 加 `bun test`，另有面板拼装门禁 `scripts/smoke-panel-build.ts`。发版在 Actions 页面手动 dispatch `release.yml`，输入 `v*` 开头的 tag；workflow 自己创建并推送这个 tag，再编译 Linux x64 / arm64、macOS x64 / arm64 与 Windows x64 的产物。Docker 与 `docker-compose.yml` 用 `--production` 安装依赖。
